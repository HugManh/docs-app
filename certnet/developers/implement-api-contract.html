Hướng dẫn tự implement API Contract

Mục tiêu: bạn triển khai surface ghép cho team khác. Docs + OpenAPI đã freeze; code chain/modules do bạn viết.

Contract: API-Contract · OpenAPI: openapi.yaml
Bản trong repo code: certnet-chain/docs/openapi.yaml

0. Nguyên tắc

  1. OpenAPI = source of truth cho path, schema, mã lỗi. Đổi behavior → sửa OpenAPI trước, rồi code, rồi sync bản docs.
  2. Ba interface trước, chain sau — wallet/verify chỉ phụ thuộc DidResolver / StatusChecker / TrustRegistry (Interface-decoupling).
  3. Public read trước — đủ để team khác ghép verify. Write/auth để sau (stub 501 hoặc chưa expose cũng được).
  4. Không nhét PII vào response.

4. Đặt code ở đâu trong certnet-chain

Repo hiện tại: SimApp-based Cosmos SDK (certnetd), chưa có x/did / x/credstatus / x/trustregistry. REST hiện chỉ là gRPC-gateway module SDK mặc định (app.go → RegisterAPIRoutes).

4.1 Gợi ý cây thư mục (bạn tạo)

4.2 Map OpenAPI → Cosmos (read)

OpenAPICosmos hướng tới
GET /v1/dids/{did}Query/Resolve (hoặc DidDocument) trên x/did + grpc-gateway annotation hoặc thin gateway gọi keeper/query client
GET /v1/credential-statuses/{id}?index=Query/Status trên x/credstatus
POST /v1/credential-statuses/checkCùng query; batch = loop hoặc Query/StatusBatch
GET /v1/trust-registry/issuers/{issuerDid}Query/Issuer trên x/trustregistry

Lưu ý path: Cosmos grpc-gateway thường mount dưới /cosmos/... hoặc custom proto google.api.http. Contract integrator dùng /v1/.... Hai cách:

  • A (nhanh để ghép): Thin HTTP server (stdlib/chi) implement đúng /v1 OpenAPI → gọi query client / mock.
  • B (chuẩn chain): Proto option (google.api.http) = { get: "/v1/dids/{did}" } rồi register trong RegisterAPIRoutes.

Chọn A trước nếu cần team khác hit API tuần này; B khi module ổn định.

4.3 Wire module vào app (checklist khi bạn scaffold)

Trong app.go (và encoding / BasicModuleManager):

  • Thêm store key + keeper
  • AppModule / AppModuleBasic vào module manager
  • Genesis defaults (có thể empty)
  • Register gRPC query + (nếu có) Msg services
  • Register grpc-gateway routes
  • Simulation / invariants: sau, không blocker contract

Tham chiếu cấu trúc module: Modules.

6. Checklist coding (tick khi tự làm)

Phase A — Contract & mock (không cần chain)

  • Interfaces DidResolver / StatusChecker / TrustRegistry trong repo client
  • Mock + unit test theo Test-Vectors
  • OpenAPI hai bản docs/code còn khớp nhau
  • Document base URL local cho team khác (http://localhost:8000/v1)

Phase B — HTTP surface khớp OpenAPI

  • GET /v1/dids/{did} (URL-encode DID)
  • GET /v1/credential-statuses/{statusListId}?index=
  • POST /v1/credential-statuses/check (single + batch)
  • GET /v1/trust-registry/issuers/{issuerDid}
  • Error body { code, message, details, correlationId }
  • Field chain có trên read (fixture: proof: null OK)

Phase C — Cosmos modules (read path)

  • Proto + x/did Resolve query
  • Proto + x/credstatus Status query
  • Proto + x/trustregistry Issuer query
  • Wire app.go + genesis
  • Gateway/query trả data từ store (không chỉ fixture)
  • Seed localnet với vectors §7 để demo

Phase D — Handover & write (sau)

  • Team khác chạy Handover-Checklist từ code họ
  • Write stubs / Msg types (DID create, status update, trust add) — auth TBD
  • Testnet base URL công bố — Testnet

7. Acceptance để “đủ ghép”

Team integrator có thể:

  1. Generate hoặc hand-write client từ OpenAPI
  2. Point adapter tới mock hoặc gateway local
  3. Pass 3 kiểm tra handover (resolve key đúng · status valid/revoked · trust accepted/rejected)

Họ chưa cần: PoA, faucet, light-client proof, write auth — các mục TBD trong API-Contract §8.

Danh tính & Chứng chỉ {#danh-tinh—chung-chi-ssi}

Thuật ngữNghĩa
SSISelf-Sovereign Identity – mô hình danh tính do chủ thể kiểm soát, không phụ thuộc nhà cung cấp trung tâm
DIDDecentralized Identifier – định danh phi tập trung, dạng did:<method>:<id>, giải quyết thành DID Document
DID DocumentTài liệu chứa verificationMethod, service, metadata – trả về khi resolve DID
did:certnetDID method của CertNet; dạng did:certnet:<network>:<unique-id> (ví dụ did:certnet:testnet:z6Mk...)
VCVerifiable Credential – chứng chỉ số có thể xác minh mật mã; gồm issuer, subject, credentialSubject, proof
VPVerifiable Presentation – gói một hoặc nhiều VC để trình bày cho verifier
IssuerBên cấp VC (tổ chức, cơ quan); phải có DID và key trong Trust Registry để được công nhận
HolderBên nắm giữ VC (người dùng, tổ chức)
VerifierBên kiểm tra tính hợp lệ của VC/VP – dùng 3 interface: DidResolver, StatusChecker, TrustRegistry
Credential StatusTrạng thái VC trên chain: valid / suspended / revoked
Status ListDanh sách bit nén (bitstring) lưu trạng thái nhiều VC; mỗi VC ánh xạ tới statusListId + index
assertionMethodVerification relationship trong DID Document – key dùng để ký VC
verificationMethodEntry trong DID Document mô tả khóa (loại, publicKeyJwk, controller)
publicKeyJwkKhóa công khai dạng JWK (JSON Web Key); CertNet dùng Ed25519
Ed25519Thuật toán chữ ký đường cong elliptic; nhanh, an toàn, nhỏ gọn – dùng mặc định trong CertNet

CertNet – Hệ thống {#certnet—he-thong}

Thuật ngữNghĩa
CertNetApp-chain permissioned (PoA) – shared trust layer cho did:certnet, Credential Status, Trust Registry
Mega appỨng dụng sản phẩm dùng CertNet qua interface; không sở hữu hay quản lý chain
Shared infrastructureCertNet chỉ có giá trị khi nhiều issuer / verifier / app cùng dùng chung
Permissioned write / public readGhi có kiểm soát (cần quyền / chữ ký); đọc công khai qua REST / gRPC
Plan A / Plan BHai phương án phí ghi: Plan A = phí cố định; Plan B = neo phí / denom (còn mở)
TestnetMạng thử nghiệm – endpoint TBD; dùng để verify trước mainnet
MainnetMạng chính thức – lịch TBD (xem Operations)
GĐ7Giai đoạn 7 – mốc mega app bắt đầu tích hợp CertNet thật; trước GĐ7 chỉ dùng interface/mock

Cosmos & Chain {#cosmos—chain}

Thuật ngữNghĩa
Cosmos SDKFramework xây app-chain module-based; CertNet dùng stack này
CometBFTEngine đồng thuận BFT (kế thừa Tendermint Core); đảm bảo finality ngay sau block
PoAProof of Authority – validator được cấp quyền tập trung, không phải PoS mở
x/didModule Cosmos SDK quản lý DID Document trên chain
x/credstatusModule quản lý Credential Status (status list, bitstring)
x/trustregistryModule quản lý Trust Registry (issuer whitelist, scope, thời hạn)
LCDLight Client Daemon – REST proxy của Cosmos node; cổng mặc định :1317
gRPCGiao thức RPC nhị phân của Cosmos; CertNet expose qua gateway thành REST
Block finalityCometBFT đạt finality tức thì sau khi block được commit (không cần confirm thêm)
TxTransaction – đơn vị ghi trên chain; cần ký bằng private key của sender

Gateway & API {#gateway—api}

Thuật ngữNghĩa
certnet-gatewayHTTP REST gateway dịch /v1/... sang gRPC/LCD của node; repo riêng certnet-gateway
Integration APISurface HTTP mà mega app / verifier gọi; local: http://localhost:8000/v1
DidResolverInterface client-side: resolve(did) → DIDDocument; không gọi trực tiếp chain
StatusCheckerInterface client-side: check(ref) → {status}
TrustRegistryInterface client-side: lookup(issuerDid) → {recognition, vcTypes, ...}
Adapter patternImplement 3 interface bằng mock local → swap sang HTTP khi có testnet; không đổi logic verify
X-Correlation-IdHeader tracing xuyên service; nên gửi từ client
Idempotency-KeyHeader write POST – tránh double-submit khi retry
chain objectField trong response resource – chứa blockHeight, txHash, proof (self-check)
proof: nullGateway chưa cung cấp light-client proof; client không được giả định đã verify
TBDTo Be Decided – phần chưa chốt (base URL testnet, cơ chế auth write, schema proof…)

Trust Registry {#trust-registry}

Thuật ngữNghĩa
Trust RegistrySổ issuer được công nhận (loại VC, scope, thời hạn, cơ quan công nhận)
recognitionTrạng thái issuer: recognized / rejected / pending
vcTypesDanh sách loại VC issuer được phép cấp (ví dụ HealthCertificate, EducationCredential)
recognizedByCơ quan / tổ chức đã xác nhận issuer (DID của governance body)
Governance bodyTổ chức quản trị Trust Registry; phê duyệt / từ chối issuer
Pending requestYêu cầu tham gia Trust Registry chưa được duyệt; lưu hàng đợi trên gateway trước khi lên chain

Quy ước & Khác {#quy-uoc—khac}

Thuật ngữNghĩa
PIIPersonally Identifiable Information – dữ liệu cá nhân; CertNet không lưu PII trên chain
W3C analogyCertNet vay mô hình quản trị đa bên độc lập của W3C – không có nghĩa chỉ viết chuẩn
SDKThư viện client (ưu tiên TypeScript npm) để gọi CertNet API; wrap 3 interface
Test vectorDữ liệu mẫu cố định để kiểm tra tích hợp (DID mẫu, status list, trust registry fixture)
LocalnetChain chạy local (1 node) dùng để phát triển và test; script localnet.sh trong certnet-chain
HandoverBàn giao spec / API / checklist cho bên tích hợp (Identra, mega app team…)

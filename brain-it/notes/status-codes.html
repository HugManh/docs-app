Chương 6. Status Codes

Purpose

HTTP Status Code là cơ chế chuẩn để Server thông báo kết quả xử lý Request cho Client.

Một API nhất quán không chỉ trả về dữ liệu đúng mà còn phải sử dụng đúng Status Code theo ngữ nghĩa của HTTP RFC 9110.

Việc lạm dụng 200 OK cho mọi trường hợp hoặc luôn trả 500 Internal Server Error khi có lỗi sẽ làm Client khó xử lý, giảm khả năng tích hợp và gây khó khăn trong việc giám sát hệ thống.

Rules

  • API MUST sử dụng đúng HTTP Status Code.
  • Status Code MUST phản ánh kết quả xử lý Request.
  • Không sử dụng 200 OK cho mọi trường hợp.
  • Không sử dụng 500 cho lỗi nghiệp vụ.
  • Client SHOULD có thể xác định lỗi chỉ bằng Status Code.
  • Response Body và Status Code MUST nhất quán.

Best Practices

  • Mỗi loại lỗi có Status Code riêng.
  • Không lạm dụng 200 OK.
  • Không trả 500 cho lỗi nghiệp vụ.
  • Ưu tiên 201 khi tạo Resource.
  • Dùng 202 cho xử lý bất đồng bộ.
  • Dùng 204 khi không có nội dung trả về.
  • Phân biệt rõ 400, 409 và 422.
  • Luôn log đầy đủ lỗi 5xx.

Checklist

  • GET trả 200.
  • POST tạo mới trả 201.
  • DELETE mặc định trả 204.
  • Async trả 202.
  • Validation trả 422.
  • Duplicate trả 409.
  • Chưa xác thực trả 401.
  • Không đủ quyền trả 403.
  • Không tìm thấy trả 404.
  • Chỉ dùng 500 cho lỗi hệ thống.

Ghi chú bổ sung: Trong các chương sau (Validation, Error Handling, Optimistic Locking…), tài liệu sẽ mở rộng cách sử dụng các mã như 412 Precondition Failed, 428 Precondition Required, 429 Too Many Requests và chuẩn hóa cấu trúc JSON của error response. Điều này giúp thống nhất từ HTTP Status Code đến nội dung lỗi trả về.

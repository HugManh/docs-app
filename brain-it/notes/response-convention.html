Chương 8. Response Convention

Purpose

Response Convention chuẩn hóa cách API trả dữ liệu về cho Client.

Một Response nhất quán giúp:

  • Frontend dễ xử lý.
  • Mobile dễ tái sử dụng.
  • API dễ mở rộng.
  • Logging và Monitoring đơn giản hơn.
  • Giảm tài liệu riêng cho từng endpoint.

Mục tiêu của chương này là thống nhất cấu trúc Response cho toàn bộ hệ thống.

Rules

  • Response MUST sử dụng JSON mặc định.
  • Response MUST phản ánh đúng HTTP Status Code.
  • Response SHOULD có cấu trúc thống nhất.
  • Response MUST NOT trả dữ liệu dư thừa.
  • Resource Representation SHOULD nhất quán.
  • Error Response MUST có cấu trúc riêng.
  • Collection Response SHOULD hỗ trợ metadata.
  • Success Response SHOULD đơn giản nhất có thể.

Best Practices

  • Mặc định trả JSON.
  • Response phản ánh đúng HTTP Status.
  • Resource trả Object.
  • Collection trả Array hoặc data + meta.
  • Dùng ISO 8601 cho ngày giờ.
  • Dùng camelCase cho tên trường.
  • Không trả dữ liệu nhạy cảm.
  • Chỉ dùng Envelope khi thực sự cần mở rộng.
  • Không thêm success hoặc message một cách máy móc.

Checklist

  • Response sử dụng JSON.
  • HTTP Status Code phản ánh đúng kết quả.
  • Resource trả Object.
  • Collection trả Array hoặc data + meta.
  • Pagination đặt trong meta.
  • Không dùng success mặc định.
  • Không trả dữ liệu nhạy cảm.
  • Sử dụng ISO 8601 cho thời gian.
  • Sử dụng camelCase cho tên trường.
  • Envelope được áp dụng nhất quán nếu chọn sử dụng.

Lưu ý thiết kế: Nên quyết định một quy ước duy nhất cho toàn bộ hệ thống:

  • Option A: Trả trực tiếp Resource ({ id, name }) cho tất cả endpoint không phân trang, chỉ dùng data khi cần meta.

  • Option B: Luôn dùng envelope ({ data, meta, links }) cho mọi endpoint.

Việc trộn lẫn hai cách trong cùng một hệ thống sẽ làm tăng độ phức tạp cho SDK, Frontend và tài liệu API. Chương 43 (Checklist) sẽ đưa ra tiêu chí lựa chọn giữa hai chiến lược này.
